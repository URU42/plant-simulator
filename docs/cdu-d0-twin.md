경보·영향 표시 규칙(관측값만 사용, 정답·주입 정보 미사용):
- **경보**: 각 태그의 실제 한계를 넘은 새 관측에서 표시, 한계 안으로 돌아온 관측에서 해제.
- **관리 기준 편차**: 물리 계산 태그의 최근 10 표본 평균이 관리 기준에서 4σ 이상. 고장 원인 판정이 아니다.
- **연결 설비 영향**: 같은 물리 회로에서 한계 경보 설비(없으면 편차가 가장 큰 설비)를 기준으로, 시간상 일치하는 다른 설비의 물리 태그 평균 변화가 2.5σ 이상일 때만 표시하고 그 사이 공정 경로를 강조한다. 공정 연결만으로는 강조하지 않는다. 독립 회로(P-8303A, F-8201)는 연결 영향을 만들지 않는다.
- 정상 처리량 변화(OP-THROUGHPUT-CHANGE)는 CDU 에서 모든 물리 태그 변화가 1σ 미만이라 경보·편차·영향이 없다.

## 3. 물리 모델

| 회로 | 구성 | 계산 |
| --- | --- | --- |
| `coupled:P-8101A` | 흡입 경계 → 스트레이너 → P-8101A → 공통 헤더 → (다른 제품 등가 분기 \| 제품 분기: 배관 → 제어밸브 → 후속 흡입 스트레이너 → P-8401A → 토출 배관) | Pump·Pipe·Valve·Network 이분법, 헤더 압력에서 두 분기 동시 해 |
| `single:P-8303A` | AT 하부 경계 → 스트레이너 → 흡입 배관 → P-8303A → 토출 배관 → 잔사유 경계 | 압력 상승 곡선 + NPSH·캐비테이션 양정·효율 감소, 유량 이분법 |
| `single:F-8201` | 대기 → 흡입 필터·댐퍼 → F-8201 → 덕트·버너 레지스터 → 가열로 통풍 −10 mmH2O | 팬 압력 곡선(회전수 상사), 비압축(차압/대기압 ≈ 1.8 %) |

캐비테이션(P-8303A): 증기압 pv(T) = pv0·exp(B(1/T0 − 1/T)), NPSHa = (p_inlet − pv)/(ρg) + v²/2g, NPSHr(Q,N) = (N/N0)²·NPSHr_rated·(0.5 + 0.5(Q/(N/N0·Q_r))²), 여유비 s = NPSHa/NPSHr 에 따라 s ≥ 1.3 에서 0, 1 ≤ s < 1.3 에서 0.03x², s < 1 에서 급경사(값·기울기 연속, 상한 0.6). 정상 NPSHa 8 m·NPSHr 4 m, 345 ℃ 잔사 밀도 780 kg/m³, B 는 흡입 온도 +15 K 에서 유량 −8 % 가 되도록 역산했다. 막힘 최대치는 여유비 0.85 에 맞췄다. 이 펌프는 흡입압 경보 하한보다 캐비테이션이 먼저 시작되며, 흡입 악화 단독에서는 흡입압 한계 경보 없이 편차로 나타난다. 지원 시나리오가 NPSHa ≤ 0 이나 양정 감소 상한에 닿으면 설정 로드를 거부한다(유효 범위 검사). P-8101A 는 캐비테이션 모델을 적용하지 않았다(흡입 악화 시 진동은 기존 경험 신호).

팬(F-8201): 25 ℃ 흡입 공기 1.184 kg/m³, 풍량 태그는 0 ℃·101.325 kPa 표준 밀도 1.2931 kg/Nm³ 로 환산, 정상 차압 184.6 mmH2O, 체절 1.25 배, 효율 0.80. 오염은 곡선·효율 15 % 저하(S1 0.6 + S2 0.4), 흡입 막힘은 풍량이 82,000 Nm3/h 가 되도록 역산. 가열로(HT)에는 센서가 없어 연소 공기 감소의 가열로 영향은 계산 상태(공기 유량)로만 남고 화면 영향 표시는 없다.

설정 생성: `scripts/calibrate_single.py`(P-8303A·F-8201), 기존 `physics_cdu_integrated.yaml` 에 후속 펌프 항목 추가.

실행 중 발견·수정한 실패: (1) E2E 가 일반 사유 문구를 기대해 설비별 제외 사유에서 실패 → 카탈로그 사유와 대조하도록 수정. (2) 30× 에서 센서 탭 화면값과 스냅샷 최근 창의 시차 → 1× 에서 화면을 먼저 읽고 대조. (3) 회복 직후 화면 카탈로그 재동기화(5 s) 전 주입 시도 → 옵션 활성화를 기다림. 세 번째 수정 뒤 새 DB 로 처음부터 다시 실행해 통과했다.

## 5. 한계·미실행

- 정상 상태 비교만 했다. 기포 동역학·침식·캐비테이션 진동·과도응답·열수지·혼상은 검증하지 않았고 진동·베어링 온도는 경험 신호다.
- 직렬 등가 회로라 P-8401A 흡입·토출 거동은 중간 드럼 없이 계산된다. 후속 펌프 마모는 전류 변화만 커서 Mock 진단은 근거 부족을 낸다.
- 흡입 유체 온도 태그 TI-8303B 는 경험 생성값이고, 물리 회로는 같은 600 s 상승의 +15 K 를 경계 조건으로 쓴다.
- D0 시점에는 Docker 데몬이 꺼져 Compose 컨테이너 기동을 실행하지 못했다. 이후 D4 단계에서 Compose 트윈 오버레이(다섯 공장)와 PostgreSQL 로 컨테이너 빌드·기동·수집기 정지/재시작·볼륨 포함 재생성을 확인했다(sk-clx-diag-agent `docs/VALIDATION.md` Docker 절). 컨테이너 대상 전체 브라우저 E2E 는 실행하지 않았다.
- 실제 LLM(`mode: live`) 진단은 provider 미설정으로 미실행(D0 차단 사유 아님). 진단은 `mode: mock` 만 보고한다.
