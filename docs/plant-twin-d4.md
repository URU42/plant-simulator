## 대표 회로 선정

회로 모양은 다섯 플랜트가 같다: 입력 펌프 → 공통 토출 헤더 → 등가 분기 둘(제품 분기에 제어밸브 → 후속 펌프 흡입 스트레이너 → 후속 펌프 → 토출 배관). 설비 ID·태그·경계압·밀도·곡선은 플랜트마다 마스터에서 따로 정했으며 CDU 값을 복사하지 않았다(테스트 `test_circuit_ids_sensors_and_boundaries_are_plant_specific`).

| 플랜트 | 입력 → 후속 | 선정 근거(마스터 공정 간선·태그) | 제외한 후보 |
| --- | --- | --- | --- |
| CDU | P-8101A → P-8401A | 기존 D2-A 회로 유지 | — |
| HOU | P-2101 → P-2701 | P-2101 → MIX → … → FRAC → P-2701 공정 간선, 두 펌프 모두 흡입·토출압·유량·전류 | P-2601(환류, 후속 회로가 FRAC 로 되돌아옴) |
| RFCC | P-1101A → P-1303A | P-1101A → RX → FR → P-1303A, 후속 유량 135 < 원료 209 m³/h | P-1301A·P-1302A(유량이 원료보다 커 단일 헤더 수지 불가), P-1501A·P-1502A(습가스 압축기 경유 기상 구간) |
| RHDS | P-3101 → P-3102 | P-3101 → MX → … → FR → P-3102 | P-3103(전류 태그 없음) |
| VRDS | P-4101 → P-4102 | P-4101 → MX → … → FR → P-4102 | P-4103(전류 태그 없음) |

회로 밖 설비(압축기·팬·구동기·기어박스·다른 펌프)는 선택·계측·진단은 되지만 트윈 주입은 막고 사유를 표시한다. 물리 계산이 없고 기존 경험 신호 모드는 이번 검증 범위가 아니기 때문이다.

## 계수 산정 (D1)

`scripts/calibrate_physics.py` 가 마스터 운전점 μ(입력 흡입·토출압·유량, 후속 흡입·토출압·유량)에서 계수를 역산해 `config/physics_<plant>_integrated.yaml` 을 쓴다(CDU 는 기존 D2-A 파일에 후속 펌프 항목만 추가). 합성 설계 선택은 스크립트의 `DESIGN` 표에 있다: 단일 밀도(HOU 900, RFCC 940, RHDS 950, VRDS 990 kg/m³), 회전수·효율·체절 비, 배관 길이, 설계 유속 기반 내경, 고정 Darcy 0.025, 분기 출구압 비율. 압력 단위는 마스터 표기를 따른다(kg/cm²(g) = 98,066.5 Pa, bar(g) = 100,000 Pa, 대기압 101,325 Pa).

고장 최대치는 해당 태그 하한 기준을 넘는 지점으로 역산했다(경보 하한과 정지 하한 사이, 정지 하한이 없으면 경보 하한 아래). 하한이 없거나 이 회로에서 도달할 수 없는 항목은 10 % 기본값을 쓰고 관리 기준 편차로만 보인다. 플랜트별 목표값은 각 YAML 머리 주석에 있다.

## 시나리오 → 물리 파라미터 (D2-A)

| 대상 | 모드 | 파라미터 | 복귀 |
| --- | --- | --- | --- |
| 입력 펌프 | PM-SUCTION-LOSS | 입력 스트레이너 저항(S1 0.45 + S3 0.55) | 정지 후 60초 |
| 입력 펌프 | PM-IMPELLER-WEAR | 입력 펌프 양정·효율 감소(손상) | 정지 후 유지, 수리 후 60초 |
| 입력 펌프 | PM-DISCHARGE-VALVE-RESTRICTION | 제품 분기 밸브 개도 감소 | 정지 후 60초 |
| 입력 펌프 | OP-THROUGHPUT-CHANGE (정상 운전 변화) | 같은 밸브 0.2 배 | 정상 운전 후 60초 |
| 후속 펌프 | PM-SUCTION-LOSS | 후속 흡입 스트레이너 저항 | 정지 후 60초 |
| 후속 펌프 | PM-IMPELLER-WEAR | 후속 펌프 양정·효율 감소(손상) | 정지 후 유지, 수리 후 60초 |
| RHDS P-3102·VRDS P-4102 | PM-SUCTION-HOT (기존) | S3 에서 후속 스트레이너 0.55 | 지원하지만 브라우저 E2E 미실행 |

- 물리 태그(압력·유량·전류)는 수력 해가 중심값을 정하고, 진동·베어링 온도 등은 기존 경험 효과를 유지한다. 전류는 정상 전류 × 축동력 비의 대용값이다.
- **회로당 한 시나리오**: 같은 회로에 진행·회복·미수리 손상 중인 물리 사건이 있으면 다른 회로 설비 주입을 409 로 거절한다(`AnomalyBook.CircuitBusy`). 파라미터 조합은 검증하지 않았기 때문이며, 시작 시 단일 최대치와 입력 펌프 세 파라미터 조합의 해 존재를 확인한다.

## 조작 카탈로그·API (D3)

- 수집기 `GET /{plant}/simulation/catalog`(운영자 토큰): 설비별 역할, 조작 상태(idle·active·recovering·damaged), 운전자가 고른 모드 ID, 시나리오별 지원·주입 가능·차단 사유. 정답 분류·기대값·효과 계획은 없다.
- `POST /{plant}/simulation/control` 의 `inject` 는 카탈로그로 서버에서 검사한다(미지원 422, 진행·회로 사용 중 409). 멈추거나 고칠 사건이 없는 `stop`·`repair` 는 409 다.
- 조작 시계는 물리 결합이 켜진 모든 공장에 생긴다(이전: CDU 만). 기존 `/anomalies` 정답 경로·SSE·`Sample` v3·시간축은 그대로다.
- 진단 저장소는 `/api/v1/twin/{plant}`(cdu·hou·rfcc·rhds·vrds)로 일반화했고 기존 `/api/v1/twin/cdu` 는 같은 경로로 동작한다. 상세는 진단 저장소 `contracts/CDU_TWIN.md`.

## 한계와 미실행

- 다섯 회로 모두 단상·비압축·정상 상태·고정 Darcy·단일 밀도의 **등가 회로**다. 반응·분리·기화·조성·열수지·이송 지연·제어 루프를 계산하지 않는다. NPSH/캐비테이션은 다섯 공장 연결 회로(입력·후속 펌프)와 CDU P-8303A 단독 회로에서 계산하고(카탈로그 `cavitation_model`), CDU F-8201 팬 회로는 계산하지 않는다.
- 후속 펌프는 중간 드럼 없이 직렬 연결되어 흡입압이 제품 유량만의 함수다. 그래서 후속 펌프 마모 시 흡입압이 오르고(HOU 는 PI-2701A 상한 경보까지), 입력 측 변화에 후속 흡입압이 민감하다. 실제 설비 거동 근거가 아니다.
- RFCC·RHDS·VRDS 는 관리 기준 σ 가 작아 정상 처리량 변화도 4σ 이상 편차로 보이며, Mock 진단이 원인 후보를 낸다(한계 경보는 없음). Mock 규칙이 정상 운전 변화를 구분하지 못한다.
- RHDS·VRDS 후속 펌프의 PM-SUCTION-HOT 은 물리 단위 테스트만 했고 브라우저 E2E 는 실행하지 않았다.
- 회로 밖 설비의 기존 경험 신호 모드는 트윈에서 주입하지 않으며 이번 검증 범위가 아니다(기존 `/anomalies` 경로는 그대로).
- 실제 LLM(`mode: live`) 진단, 다중 사용자 동시 조작, 수집기 재시작 후 명령 영수증 영속화, 운영 배포는 실행하지 않았다. 플랜트별 조작 허용 목록(`TWIN_CONTROL_PLANTS`)은 Backend 단위 테스트만 했다.
