# 시나리오 주입형 전환 — 작업 기록

근거: 위키 raw 초안 `plant-simulator-scenario-driven-redesign-20261119`(uru42-wiki `docs/`, 검토용, 팀 승인 전)의 사용자 확정 사항 D1~D11 (2026-11-19 대화).
브랜치 `feat/scenario-driven`. 이 문서는 무엇을 바꿨는지, 진행 중에 대신 정한 것, 검증과 남은 일을 적는다.

## 검증

- `uv run pytest`: 214 통과 (이전 216 중 자동 이상·지속 고장·Nelson 알람·Redis 테스트를 지우고 고장 모드·생성기·장부·설정 테스트로 바꿨다).
- 정상 생성(Mac, 생성만): RFCC·RHDS 각 6시간, 규칙 1~3 위반 0 건. 같은 공정 그룹 신호 태그 간 부호 보정 상관 평균 0.49, 다른 그룹 0.00. z 표준편차 평균 0.985.
- 생성 속도: RFCC 167k 표본/초 (main 의 8규칙 생성기 98k).
- 고장 모드 점검(스크립트, 저장소 밖): `T-1401` 수분 유입 — S0 동안 터빈 태그 위반 0·진동 평균 +0.6σ, S2 부터 규칙 1, S3 에 `C-1401` 진동·유량 반응, 압축기 회전속도는 터빈과 같은 값. `P-8101A` 흡입 악화 — 끝값 흡입 1.56(알람 1.62 아래)·진동 4.64(알람 4.5 위)·유량 240(알람 248 아래).
- 실행하지 않은 것: 다섯 공장 통합 실행 하루 백필·k8s 배포 실측, Frontend·Backend·Alarm Worker 연동.

## 남은 일

- 배포: PVC 의 DB 를 지우고 재백필(v4). Alarm Worker 는 `plant-sim:alarms` 입력이 없어진다 — 새 탐지 파이프라인으로 바꿀 시점을 Backend 와 정해야 한다.
- 데모용 시나리오 자동 실행(시간표) 필요 여부는 팀 미합의.
- RFCC 는 한계가 좁아(통계 σ) 고장 효과가 금방 정지에 닿는다. 정상 운전 변화(`OP-LOAD-CHANGE`)는 효과를 −1.5σ 로 줄여(사용자 요청 2026-11-19) 알람·정지에 닿지 않고 Nelson 규칙 2 로 1분 안에 잡힌다. RFCC 에서는 표본 약 1 % 가 경고(통계 ±3σ)를 넘는다.
- 손상처럼 멈춘 뒤에도 남는 단계, `CDU-FEED` 같은 공정 노드 경유 전파는 아직 없다.
- 왕복동 압축기의 압력 맥동 → 배관 진동 → 배관 피로 균열은 배관 진동 태그가 없어 만들지 않았다. 각 모드의 `unobserved` 가 태그 추가 후보 목록이다.
- `table-plan.md`·`plant-simulator-plan.md` 의 이상 판정 부분은 머리말에 변경 표시만 했다.
